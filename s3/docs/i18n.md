# Languages (S3)

EspOS on the S3 shows its text in the language of the setting `sys.lang`. English is built into the firmware; every
other language is a package from the store: `dev.espos.lang.<tag>` with the strings, plus a font package when the
built-in fonts lack the language's letters. The owner's choice (2026-11-18): English first, Vietnamese second, then
the popular ones.

| tag | language | language package | font package |
|---|---|---|---|
| `en` | English | built in | built in |
| `vi` | Tiếng Việt | `dev.espos.lang.vi` (48 KB) | `dev.espos.font.vi` (170 KB) |
| `zh-Hans` | 简体中文 | `dev.espos.lang.zh-Hans` (40 KB) | `dev.espos.font.sc` (1.47 MB) |
| `es` | Español | `dev.espos.lang.es` (44 KB) | built in |
| `fr` | Français | `dev.espos.lang.fr` (45 KB) | built in |
| `de` | Deutsch | `dev.espos.lang.de` (43 KB) | built in |
| `ja` | 日本語 | `dev.espos.lang.ja` (51 KB) | `dev.espos.font.jp` (1.22 MB) |
| `ko` | 한국어 | `dev.espos.lang.ko` (46 KB) | `dev.espos.font.kr` (0.79 MB) |
| `pt-BR` | Português (Brasil) | `dev.espos.lang.pt-BR` (43 KB) | built in |
| `ru` | Русский | `dev.espos.lang.ru` (67 KB) | `dev.espos.font.cyr` (88 KB) |
| `id` | Bahasa Indonesia | `dev.espos.lang.id` (41 KB) | built in |

The same list for the web: `i18n/languages.json` (`tools/i18n.py languages`).

## The setting `sys.lang`

- Value: one of the tags above. Missing, empty or unknown = `en`.
- Set on the web: the device follows at its next sync. When the language's packages are missing it downloads them
  first (font package, then the language), then switches; the screens are rebuilt when nobody is touching the
  screen (like a theme change). A failed download is tried again after 30 minutes; meanwhile the device keeps the
  language it shows.
- Set on the device (Settings › Language): the device downloads what is missing (a progress screen), switches, and
  only then stores `sys.lang` with `desk::setSetting`, so the change goes up with the next sync's `settings` like
  every other device-side change (`{"k": "sys.lang", "v": "vi", "age_s": n}`). A failed download changes nothing.
- The device never shows a language whose packages are not in: it stays on the language it shows (English at worst).
  A font package on a memory card counts once the card is read (a few seconds after boot: until then English).
- The switch needs no restart: `i18n::use()` loads the pack, the font fallbacks change, package names are relabelled,
  the store's catalog is read again, and `os::rebuild()` makes every screen again.

## Fonts

- Built in: Ubuntu at the text sizes with Latin-1 (English, Spanish, French, German, Portuguese, Indonesian), and
  the digit fonts. **The Vietnamese letters left the firmware on 2026-11-18** (159 KB): they are the font package
  `dev.espos.font.vi` (Ubuntu + Ubuntu-Vietnamese at the same sizes). The built-in fonts keep the line height they had
  with them, so no layout moved.
- Vietnamese text appears whatever the language (the dogs speak Vietnamese; news, calendar events, city names): since
  2026-11-19 its letters come from `dev.espos.font.vi` whenever that package is in, read size by size on the first
  Vietnamese letter drawn at that size (~10 KB of PSRAM a size, only the sizes used; `src/fonts.cpp` viLetter). Without
  the package the letters show without their marks ("Hà Nội" → "Hà Noi"), never boxes, and the device fetches the
  package once a boot, quietly (`src/i18n.cpp` fetchVietnamese: 164 KB on Máy's LittleFS, or the card), then redraws.
- Every text size's chain: the built-in font → [the language names, 15 px] → the language's font (or the bare
  Vietnamese letters) → LVGL's symbols. A font package's file sizes: `r<px>.bin` / `b<px>.bin`; a text size takes the
  nearest one of the same weight. CJK: Noto Sans SC/JP/KR (SIL Open Font License) at 12, 14, 20 px, regular only,
  with the common characters (GB 2312 level 1, JIS X 0208 level 1 + kana, KS X 1001 Hangul) and every character the
  translations, the sample apps and the package names use. Cyrillic and Vietnamese: Ubuntu at every size and weight.
- The languages' own names (简体中文 日本語 한국어 Русский Tiếng Việt) are a 1.6 KB built-in font (`src/fonts/lang_names.c`)
  so Settings › Language can list them before anything is downloaded.
- Where a package lives: languages and small fonts (≤ 384 KB) on Máy in LittleFS (`store::onLfs`), copied to PSRAM when
  loaded; a CJK font in the app area (memory-mapped: no RAM at all) or, when that is full (PawBoop), on the card
  (copied to PSRAM, 0.8-1.5 MB). Never internal RAM.

## Marking text in the sources

The text in `src/` is English. Every piece of text the user reads carries a mark that `tools/i18n.py extract`
collects into `i18n/en.json`:

| mark | what it does | use it for |
|---|---|---|
| `T_("Settings")` | a call: the current language's text, or the English | text going into `String`s, `snprintf` formats, `lv_label_set_text`, anything not listed below |
| `N_("Settings")` | nothing (a mark only, no code) | text handed straight to a helper that translates literals itself, and tables of text |
| `NP_("{n} app\|{n} apps")` | nothing | the forms for `i18n::plural(n, ...)` |
| `TC_("month", "May")` | like `T_` with a context | the same English with two meanings |
| `NC_("cc", "Settings")` | a mark with a context | the same, handed to a translating helper (only there: the string carries its context) |

Helpers that translate text lying in the firmware image (string literals and tables, never text made at run time
such as names, SSIDs or server text): `kit::label`, `setText`, `listRow`, `caption`, `hint`, `button`, `chips`,
`column`, `fitText`, `wrapText`, `textW`; `wid::cap`, `fit`, `at`, `right`, `fitIn`, `measure`, `posterPx`,
`poster`, `empty`; `os::screen`, `navAction`, `toast`; `notif::post`, `schedule`; `i18n::fmt`, `plural`, `date`.
(`i18n::inImage` tells: the firmware's rodata on the board, the executable's `__TEXT` in the simulator.)

```cpp
lv_obj_t* r = listRow(body, N_("Brightness"), "", onBright);       // the helper translates
setText(state, ok ? N_("Connected") : N_("Not connected"));
String s = T_("Today");                                             // a String: translate now
snprintf(b, sizeof b, T_("%d%% charged"), pct);                     // a format: translate now
static const char* const NAMES[] = {N_("Games"), N_("Tools")};     // a table: marked...
label(c, NAMES[i], 14);                                             // ...and translated by the helper
lv_label_set_text(l, T_(NAMES[i]));                                 // ...or by T_ where no helper is
String n = i18n::plural(count, NP_("{n} app|{n} apps"));
String d = i18n::date(N_("{W}, {M} {d}"), day.d, day.m, day.y, day.wday);   // "Tuesday, Nov 18"
String t = i18n::fmt(N_("{0} needs {1} more"), where, size);        // "{0}" "{1}" "{2}" may be reordered
label(c, String(lang->name).c_str(), 15);                          // a literal that must NOT be translated: a copy
```

- A translator's note: `// i18n: ...` at the end of the line, or on a comment line just above.
- `i18n::List` for fixed lists (weekdays, months, lunar stems and branches, solar terms, sayings, number words):
  English array in the code, `"@key"` in the pack (`"a|b|c"` in `i18n/<tag>.json`). `kit::WEEKDAY[i]`,
  `WD_SHORT[i]`, `i18n::MONTH[m - 1]`, `i18n::MON_SHORT[m - 1]`, `data::CAN`, `CHI`, `SOLAR_TERM`, `QUOTES`.
- Dates: `i18n::date(pattern, d, m, y, wd)` with `{d} {m} {y}` numbers, `{M}` short month, `{MM}` month, `{w}` short
  weekday, `{W}` weekday. Reuse these patterns: `"{W}, {M} {d}"` (Tuesday, Nov 18), `"{w}, {M} {d}"` (Tue, Nov 18),
  `"{M} {d}"` (Nov 18), `"{MM} {y}"` (November 2026), `"{M} {d}, {y}"` (Nov 18, 2026), `"{W}, {MM} {d}, {y}"`.
  Forecast days from the server: `data::dayName()` names them from their date.
- Numbers: `data::num()` and `pkg::sizeText()` use the language's separators (`i18n::groupSep()`, `decSep()`).
- Upper case: `kit::upperVi()` (= `i18n::upper`, also Cyrillic).
- Logs (`trace::add`, `Serial`) stay English and unmarked.
- Never "…": text is shrunk or wrapped. `fitText` tries smaller sizes, then 1 px tighter letters, then more lines;
  `kit::button` fits a label wider than its button, `listRow` makes a long name and value share the row, `wid::cap`
  closes up its letters. German and Russian run ~30% longer than English, CJK at 12-13 px uses the 12 px CJK font.
- The keyboard types Telex (Vietnamese) by default only when the language is Vietnamese; the VI/EN key switches.

## Packages' own names

A package's manifest (and its catalog entry) may carry `"i18n": {"vi": {"name": "Tập trung", "desc": "..."}, ...}`:
the device shows the name and description of the language shown (`pkg::list()`, the store's entries) and the English
`name`/`desc` otherwise. The installed record keeps the names as `"names"`. `apps/catalog-text.json` gives English
store texts (and Vietnamese ones) to packages built elsewhere whose manifests are Vietnamese (PawBoop, the run game,
the Java runtime and games). JavaScript apps read the language as `app.lang` ("en", "vi"...); the sample apps in
`apps/` (English, with `TEXT` tables for the ten other languages) show how.

## Translations

`i18n/<tag>.json`: `{"English": "translation", ...}` (keys exactly as in `i18n/en.json`; `en.json` lists where each
is used and the notes). Lists as `"item|item|..."`; plural entries as the language's forms joined by `|`: one form
(vi, zh-Hans, ja, ko, id), one|other (en, de, es), one|other with 0 as one (fr, pt-BR), one|few|many (ru).
`"@num"` (group then decimal separator) and `"@plural"` default to the language's usual ones. How to translate: `i18n/TRANSLATING.md`. The Vietnamese is the device's own text from before the switch to English.

```
python3 tools/i18n.py extract          # after changing text in src/
python3 tools/i18n.py status           # per language: errors, missing, unused
python3 tools/i18n.py lint             # Vietnamese literals in src/ without a mark
python3 tools/i18n.py build all        # language packages into build-pkgs/espos/s3 (checks placeholders, forms, letters)
python3 tools/i18n.py font all         # the font packages (needs data/fonts/noto: Noto Sans CJK SC/JP/KR, OFL)
python3 tools/i18n.py catalog          # build-pkgs/espos/s3/catalog.json again with everything there (apps/pack.py)
python3 tools/i18n.py languages        # i18n/languages.json
```

A missing entry shows the English. The checks refuse: changed placeholders (`{0}`, `{n}`, `%d`... in the same order
for printf; date parts may change form), the wrong number of plural forms or list items, "…", and letters neither
the built-in fonts nor the language's font package have. Upload (the owner): `ESPOS_BBK=... python3
scripts/upload_apps.py s3/build-pkgs/espos/s3`.

## Packages

- Language: `{"id": "dev.espos.lang.vi", "name": "Vietnamese", "kind": "native", "engine": "lang", "type": "pack",
  "min_fw": 500, "lang": "vi", "font": "dev.espos.font.vi", "i18n": {...its name in every language}}` with one file,
  `strings.bin` (`src/i18n.cpp` has the layout: hashes of the English, sorted, then the texts).
- Font: `engine "font"`, files `r<px>.bin` / `b<px>.bin` (`src/fonts.cpp` has the layout: LVGL's own glyph
  descriptions and 4 bpp bitmaps, used in place), `LICENSE.txt`.
- `type "pack"`: never listed in the store or on Home, updated by itself when the catalog has a newer one, removable
  from Settings › Storage. Settings › Language is where they are chosen.

## Checking the screens

`tools/i18n_tour.py TAG [--packs]` runs the headless simulator (sim/build-i18n, data sim/data-i18n with the packages
installed: `--packs` builds and installs them again) over ~65 screens in that language, and writes contact sheets
and `overflow.txt` to sim/shots/i18n-TAG: the simulator's `overflow NAME` command lists text cut by its box, running
out of its parent or over other text. `--live` prints the script for `tools/sim-live.sh` (the visible window). `--rot N` turns the whole tour (1 and 3:
landscape, the gestures moved to 480 x 320), `--sim PATH` and `--data DIR` take another simulator build and data copy
(the tour writes `sys.lang` into the data). Checked 2026-11-18 in landscape (rotation 1) in en, vi, de and ja, and
rotations 2 and 3 in en: no cut or overlapping text.
Checked 2026-11-18 in all eleven languages: no findings but the landscape hourly temperatures' 2-3 px (as before, in
English too). Korean was left out of sim/data-i18n on purpose: `set sys.lang ko` downloads its font and pack from
the canned store (`sim/data-i18n/net`) and switches.
`--onboard` tours the first-boot setup's 17 screens instead (src/onboard.cpp, docs/onboarding-plan.md; it sets a claim
code so the activation step shows). Checked 2026-11-21 in all eleven languages, rotations 0 and 1, on the 3.5" and
2.8" builds, with packs 1.0.9: none of the setup's screens has an overflow line.
