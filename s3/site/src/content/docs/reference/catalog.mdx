## A package entry

| Field | From | Meaning |
|---|---|---|
| `id`, `name`, `version`, `code` | the core manifest | As in the [manifest](/reference/manifest/). The store offers an update when `code` is higher than the installed one. |
| `kind`, `engine`, `min_fw` | the core manifest | A device that lacks the engine or is older than `min_fw` shows "Needs a software update". |
| `category`, `author`, `desc`, `icon`, `perms` | the core manifest | Shown in the store. |
| `addon_of` | the core manifest | Lists the package inside its main app's page instead of on its own. |
| `type` | the core manifest | `pack`: never listed, installed with what needs it, updated by itself. |
| `i18n` | the core manifest | `name` and `desc` in other languages, by language tag. The store shows the ones of the device's language. |
| `lang`, `font` | the core manifest | A language pack's tag, and the font pack it needs. |
| `date` | the build tool | The day the entry was made (`YYYY-MM-DD`). |
| `icon_url` | the publish script | The store's picture of the icon (`<id>-<version>.jpg`). |
| `shots` | the publish script | Screenshot URLs. |
| `parts` | the publish script | One entry per `.espk` file. |

### A part

| Field | Type | Meaning |
|---|---|---|
| `id` | string | The part's name (`core`, `roads10`). |
| `url` | string | Where to download the `.espk`. |
| `size` | integer | Its size in bytes. The store shows it and checks the room before downloading. |
| `sha256` | string | Hex SHA-256 of the whole `.espk`. The installer refuses a part that does not match. |
| `req` | boolean | Required. Default: `true` when the part has no `group`. |
| `group` | string | The part is one choice of this group. |
| `default` | boolean | The group's default choice. |
| `label` | string | The choice's text in the store. Default: the part's `id`. |

**An install takes every required part plus one part of each group**: its `default` unless the user picks another.

The example holds two entries: the run game (an add-on of PawBoop, with a choice of road pictures) and the Japanese language pack, with the server address replaced by a placeholder and the `i18n` lists shortened.

## Making an entry

`tools/espk.py --entry BASE_URL core.espk [part.espk ...]` prints the entry for a package from its parts (core first), with sizes, hashes and `i18n`. The publish script then adds `icon_url` and `shots` and merges the entry into the catalog. The repository's `apps/pack.py` builds the whole catalog for the sample apps, the native packages, and the language and font packs. See [Publish to the store](/guides/publishing/).

## User packages

A user's own packages (Java games uploaded on the web desk) are not in the catalog. They reach that user's devices in the sync answer as `user_pkgs`, a list of entries in the same shape, with ids that start with `u.`.
