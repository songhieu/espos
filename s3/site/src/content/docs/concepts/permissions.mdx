A package lists what it may do in the `perms` field of its manifest. The firmware checks a permission inside the API call itself, so an app cannot reach the feature any other way.

```json
"perms": ["sound", "notify"]
```

## What is enforced today

<Aside type="caution" title="What the firmware checks">
The firmware checks **`sound`** and **`notify`**, and from 0.6.0 (API level 2) the network and file permissions below. `bg` grants nothing yet: there is no background API for apps. There is no consent screen at install and no per-app permission switch yet. Both are planned.
</Aside>

| Permission | Allows | Without it | Status |
|---|---|---|---|
| `sound` | `sound.chime()`, `sound.beep()`, `sound.click()` | the call throws `TypeError: app has no "sound" permission` | <Status s="available" /> |
| `notify` | `notify()`, `notify.schedule()`, `notify.cancel()`, `app.badge()` | the call throws `TypeError: app has no "notify" permission` | <Status s="available" /> |
| `net:<host>`, `net:*.<domain>` | [`net.request`](/reference/js-api-2/#netrequest) over https to that host, or every host under the domain | the promise rejects with `code: "denied"` | <Status s="preview" label="0.6.0" /> |
| `net:setting:<key>` | `net.request` to the host of the address the person set in that setting | rejects with `denied` | <Status s="preview" label="0.6.0" /> |
| `net:lan` | `net.request` to local addresses, http allowed | rejects with `denied` | <Status s="preview" label="0.6.0" /> |
| `net:*` | `net.request` to every public host | rejects with `denied` | <Status s="preview" label="0.6.0" /> |
| `storage:<KB>` | [`fs`](/reference/js-api-2/#fs) `data/` up to that size (4096 at most) | 64 KB | <Status s="preview" label="0.6.0" /> |
| `cache:<KB>` | `fs` `cache/` and `net.request`'s `save` up to that size (1 MB in flash without a memory card) | no cache: writes throw | <Status s="preview" label="0.6.0" /> |
| `net` | nothing (the level 1 name, reserved) | | <Status s="planned" /> |
| `bg` | nothing yet (reserved: run in the background) | | <Status s="planned" /> |

The package tool rejects a manifest with any other permission name. A device ignores names it does not know.

What a user can already switch off: an app's **notifications**, in Settings › Notifications on the device or on the web desk. Then `notify()` and `notify.schedule()` return `false` and post nothing. The switch is the `s3.notif` setting, synced both ways.

## Test before you call

There is no `app.can()` yet. Call inside `try` if your app should keep working without a permission:

```js
function chime() {
  try {
    sound.chime();
  } catch (e) {
    toast('Sound is not allowed for this app');
  }
}
```

## The planned model<Status s="planned" />

The platform plan turns permissions into a full broker, like a phone's:

- **Declared** in the manifest, as today.
- **Shown in plain words** in the store, on the device and on the web.
- **Accepted at install**, on the device or on the web desk.
- **Switchable per app** in Settings › Apps, taking effect at once.
- **Checked in every binding** (C++, JavaScript, WebAssembly) through one function, `perm::check(app, perm)`. Code can test first with `app.can(perm)`.
- **System apps go through the same broker.** Unknown package ids are not trusted.

### Permission list, version 1

| Permission | Grants |
|---|---|
| `notify` | Notifications, with a daily cap. |
| `sound` | The system sounds. |
| `bg` | A short background job on a schedule. |
| `screen.awake` | Keep the screen on while the app is open. |
| `remote` | Take part in remote control. |
| `net:<host>` | HTTPS to one host, through the OS network queue. The device's own token is never exposed. |
| `net:*` | HTTPS to any public host. |
| `net:lan` | The local network. Private addresses are blocked without it. |
| `storage:<KB>` | A storage quota. The default is 64 KB. |
| `data:weather`, `data:calendar`, `data:markets`, `data:news` | The data the OS already syncs. Calendar gives events only, never the calendar's link. |
| `location:city` | The city the user picked, not a precise position. |
| `wifi.info` | The network name and signal, never the password. |
| `theme.write` | Change the system theme. |
| `sensor:<channel>` | Read a typed sensor channel, such as `sensor:temperature`. |
| `actuator:<channel>` | Control a device, such as a relay. The user also confirms each device the first time. |
| `hw:*` | Raw bus access. Drivers only, signed, and only for devices the OS bound to them. |

The hardware permissions are explained in [Hardware and drivers](/roadmap/hardware/#permissions-in-three-layers).

### What "done" means for the broker

The plan lists the checks the broker must pass:

- a call without the permission is refused;
- switching a permission off works at once;
- a package edited on the memory card is refused (bad signature);
- uninstalling removes the app's data and its scheduled notifications.
