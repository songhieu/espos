A device works on its own, but it is at its best linked to an **EspOS server**. The server:

- pairs the device with the user's account;
- keeps the device's settings (`s3.*` and `sys.*` keys) in sync with the web desk, newest write wins;
- serves data feeds: weather, calendar, markets and news;
- serves the store catalog and the package files, language and font packs included;
- relays remote control, so the user can see and touch the screen from a browser;
- offers firmware updates (OTA), one image per device kind.

## The hosted service<Status s="available" />

| | Address |
|---|---|
| The web desk | `https://espos.dev/app` |
| These docs | `https://espos.dev/docs` |
| The device API, the store and the package files | `https://api.espos.dev` |

**Accounts** use an email address and a password. Signing up sends an email with a link to confirm the address, and "forgot password" sends a link to set a new one. There is no sign-in with Google or another provider.

**Linking a device:** with WiFi set up, Settings › EspOS account on the device shows a code and a QR code. Scan it, or enter the code on the web desk (Devices, Add device), and confirm. The code changes every 10 minutes. The web's USB installer can also link a device while it sets it up.

## Self-hosting<Status s="preview" />

The open-source repository, [github.com/songhieu/espos](https://github.com/songhieu/espos), holds a self-hosted server under AGPL-3.0 (`server/`): one Go binary with the web app built in, one account, and all data in one folder. It runs the same device workflows as the hosted service. Today it is made for the **Xteink X4** reader, whose firmware is in the same repository; an S3 against your own server is not checked end to end yet.

```sh
cd server
cp .env.example .env            # set ESPOS_PASSWORD
mkdir -p data && sudo chown 10001 data
docker compose up -d --build    # or: make && ESPOS_PASSWORD='a long password' ./espos
```

How to run it, configure it and connect a device: [Self-hosting](/roadmap/self-hosting/).

## No paid-only device features

The hosted service may charge for running costs, such as data feeds or managed hosting. No device feature will be locked behind it: the firmware, the SDK and the self-hosted server stay open.
