EspOS is not tied to one board. The goal is an OS that runs on many chips and displays, and that the community can **rebuild for their own hardware** while keeping the same platform: the same API, the same packages, the same store and the same server protocol.

Today it runs on two ESP32-S3 boards with colour touch screens. This section explains how the firmware is layered, what is board-specific today, and how a new board was added, so you can add yours.

A port touches the **board support** layer only. Everything above it is shared, which is what keeps packages working on every board: an app from the store does not know which board it runs on.

## What a port must keep

These are the platform's contract with packages. A port that changes them breaks apps.

| Contract | Today |
|---|---|
| The EspOS API | API level 1, unchanged. See [API levels](/concepts/api-levels/). |
| The logical screen | 320 × 480 in portrait, 480 × 320 in landscape, in four orientations. A smaller panel shows it scaled, as the 2.8" board does. |
| Memory for apps | 1.5 MB of JavaScript heap in PSRAM, a 16 KB stack in internal RAM. |
| Package format and storage | `.espk` files; the internal app area and `/sdcard/espos/pkgs/` on the card. |
| Fonts and system colours | The same pre-rendered fonts, the same language and font packs, and the light and dark looks. |
| The server protocol | Pairing, settings sync, the store catalog, OTA. A port reports its own board name in every sync. |

## What a port changes

A port adds one folder, `src/boards/<name>/`, and lists it in `src/boards/boards.cpp`. <Status s="preview" label="In progress" />

| Part | Where |
|---|---|
| The board's description: name, chip, capabilities, panel, pins | `src/boards/<name>/<name>.h` (a `hal::Board` descriptor) |
| Telling it apart from other boards at boot | `src/boards/<name>/bsp.cpp` (`probe()`), and its place in `src/boards/boards.cpp` |
| The panel driver | `src/boards/<name>/display.cpp` (a `hal::Display`) |
| The touch driver | `src/boards/<name>/touch.cpp` (a `hal::Input`) |
| Scaling to a smaller panel | the descriptor's `ui`, with `src/scale.h` |
| Audio, memory card, battery | descriptor values, read by `src/sound.cpp`, `src/pkg/card.cpp`, `src/power.cpp` |
| QEMU and the build | `src/boards/qemu/`, `platformio.ini`, `tools/qemu/` |

Each is described in [Board-specific code](/hardware/board-code/), and the whole path in [Port to a new board](/hardware/porting/).
